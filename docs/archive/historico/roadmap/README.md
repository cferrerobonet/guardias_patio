## 💡 Proponer Nuevas Features

¿Tienes una idea para mejorar el sistema?

1. **Revisa** el roadmap actual para ver si ya está planificada
2. **Busca** en [GitHub Issues](https://github.com/tu-repo/guardias-patio/issues?q=is%3Aissue+label%3Afeature-request) si alguien ya lo propuso
3. **Crea** un nuevo issue con la etiqueta `feature-request`:
   - Describe la funcionalidad
   - Explica el problema que resuelve
   - Propón una solución (opcional)
   - Indica usuarios afectados (cuántos se beneficiarían)

## 🔄 Proceso de Desarrollo

### Ciclo de Release

1. **Planning** (1 mes antes)
   - Definir features de la versión
   - Estimar esfuerzo
   - Asignar tareas

2. **Development** (2-3 meses)
   - Implementación de features
   - Code reviews
   - Testing continuo

3. **Feature Freeze** (2 semanas antes)
   - No nuevas features
   - Solo bug fixes
   - Documentación

4. **Release Candidate** (1 semana antes)
   - Testing final
   - Preparación de notas de versión
   - Validación con usuarios beta

5. **Release**
   - Tag en Git
   - Publicación de binarios
   - Anuncio en canales oficiales
   - Actualización de docs

### Cadencia de Releases

- **Major** (vX.0.0): ~1 año
- **Minor** (v2.X.0): ~3-4 meses
- **Patch** (v2.6.X): según necesidad (bugs críticos)
